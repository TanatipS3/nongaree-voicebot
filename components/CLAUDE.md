## LumoFace

**`LumoFace` no longer animates.** It still exports `LumoFaceHandle` with `setMode` / `setAmplitude` / `setGazeState`, but all three are **no-ops**. `VoiceRoom` still drives them (amplitude via a `requestAnimationFrame` loop, mode from `emotion` packets, gaze from turn state), so the whole emotion pipeline is live end-to-end and simply has no visual effect. The SVG eye/face assets it used to drive are still in `public/avatar/` and `avatar_extraction/`. Treat the call sites as the intact seam for restoring animation — don't delete them as dead code.

## VoiceRoom turn lifecycle

- **Frontend answer retention.** `beginPendingAnswer()` / `commitPendingAnswer()` keep the previous question *and* answer on screen until the first token of the new one lands. Three things had to change together and must not be undone individually: `chat_status` is suppressed while an answer is retained (it was a second wipe), `awaitingAnswer` is part of the settle-timer check *and* its dep array, and the 35s timeout commits the swap rather than leaving stale content attributed to a new question. The agent sends `chat_user` on *any* committed STT transcript, so a partial recognition used to erase an answer the user was still reading.
- **Frontend turn state — three ways a single turn used to freeze the whole UI.** `willQueue = turnActive || …`, and `turnActive` only clears through the settle timer, which only starts when **every** `rawBusy` term is false (`isAgentSpeaking`, `awaitingAnswer`, the `กำลังเตรียมคำตอบสั้น...` speech placeholder, the panel placeholders). If any term can get stuck, every later question is queued client-side forever and the agent never hears it. All three were found by a browser regression pass (`HANDOFF.md` §3e Fixes 21–23) and each has a deterministic repro:
  - **The speech placeholder lives only in STATE.** `sendTextMessage` / `chat_user` deliberately leave `speechPreviewRef` as `''` so `voice_delta` can append into it. Anything that needs to clear the placeholder must test the state (use an updater), never the ref.
  - **The analyser watches ONE track, but several agent tracks can be subscribed** while the token route removes duplicates. `TrackUnsubscribed` must only stop the analyser for its own track, and `stopAnalyser()` must reset `isAgentSpeaking` — a stopped analyser can't update it, so it would freeze at its last value.
  - **The 35s response timeout is the only backstop, so it stays armed until BOTH halves report** (`noteAnswerProgress('panel' | 'voice')`). It used to be cancelled by the first panel token, so a turn whose spoken side produced nothing left the placeholder up with nothing able to clear it. The agent side of the same fix is the always-sent `voice_answer`.
- **Agent-presence watchdog (`VoiceRoom.tsx`, `HANDOFF.md` §3e Fix 25).** The token route dispatches only when it sees no agent participant, but an agent whose user just closed the tab lingers up to ~25s — a quick reopen reuses it, it leaves, and nothing dispatches again. So when the room has had **no agent for 20s** (after the last one leaves, or right after joining), the page **re-requests `/api/livekit/token` without leaving the room** (token ignored; the route's dispatch logic does the work), retrying every 30s, capped at 3, reset when an agent joins. **Never "simplify" this into a reconnect** (`connectAttempt`): leaving the room ends the next agent's job too and recreates the race. It must only fire when *no* agent remains — duplicate removal with a survivor is routine.
